# RYBKA — каталог и кабинет соискателя

## Запуск

```sh
python3 -m pip install --target .runtime/deps -r requirements.txt
python3 server.py
```

Откройте http://127.0.0.1:8765/. Для PDF нужен pypdf. DOCX и TXT разбираются средствами стандартной библиотеки Python. Резюме можно заполнить вручную. Скачать сохранённое резюме в PDF можно из подвала. Для выгрузки используются ReportLab и системный шрифт Arial, DejaVu Sans или Liberation Sans.

## Как устроен кабинет

Регистрация начинается с телефона и электронной почты. После создания пароля пользователь может заполнить резюме или загрузить PDF с текстовым слоем, DOCX или TXT, проверить извлечённый текст и сохранить. Для входа подходят почта или телефон и пароль. В локальной версии контакты не подтверждаются по SMS или письму.

Аккаунты, хеши паролей, сессии и текст резюме хранятся в локальной SQLite в `.runtime/`. Оригиналы файлов не сохраняются. Одна запись резюме на аккаунт редактируется из кабинета. Сервер слушает только loopback. Автономный HTML предыдущего пилота не поддерживает API кабинета.

## Совпадение вакансий

`matching.py` нормализует текст, узнаёт навыки по словарю синонимов и сравнивает их с требованиями вакансии. По своему направлению результат складывается из 30 баллов за профессию и до 70 баллов за долю совпавших навыков. Для другого направления максимум восемь баллов. Карточки показывают процент, а в деталях видны совпавшие и ненайденные навыки. Для исходных 19 карточек требования размечены явно. При добавлении вакансий желательно уточнять их требования в словаре, по умолчанию скрипт читает навыки из тегов и текста требований.

## Каталог

Данные в `data/catalog.json`. Команда `node scripts/build.mjs` проверяет поля и дубли, затем собирает данные для сайта. После смены каталога перезапустите сервер. Расписание обновления не подключено.

Для публичного размещения этой версии нужен сервер с HTTPS, постоянной БД и подтверждением контактов. Статический артефакт не включает API кабинета.
